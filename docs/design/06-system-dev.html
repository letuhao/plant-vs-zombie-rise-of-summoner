What each one must contain

PartRule

The current build has zero notification surfaces, so a failed mutation is indistinguishable from a slow one — while the FE's own architecture doc names an HTTP error toast as the acknowledgement mechanism. It was specified and never built. GG-16

E · Developer tree `

Off by default, absent from player navigation, and governed by its own rules — density beats polish, engine vocabulary is correct, raw JSON is welcome. It still obeys the structural rules: it is a layer, Esc pops it, it is keyboard-operable, and it declares its behaviour at a thousand rows. GG-40 · GG-41

This is where nine routes went. /status, /log, /pvz-activity, /icon-dump, /almanac-dump, /cheats, /sim, /stats and the raw half of /runs. Nothing was deleted; it stopped being the game.
The inert statuses are visible here and nowhere else. Eight of the twenty-one declared statuses do nothing at runtime. A player must never be shown an affliction that has no effect; an author must never be hidden from one.

F · What this plate settles

QuestionAnswer
What may interrupt the player?Run results only. Everything else is band 4
How are rewards presented?Sequenced, counted, skippable, one at a time
What does a failure toast contain?What happened, to what, and what it changed — including "nothing"
Where does connection state live?Settings → Connection, and the developer tree. Never the top bar
How is developer mode reached?A settings toggle, persisted, default off; then the backtick key
Which cheats are player-facing?None. Presentation preferences are, and they live in Settings
