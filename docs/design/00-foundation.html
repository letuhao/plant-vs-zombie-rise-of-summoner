Foundation plate

Every shared component, drawn from the domain rather than from screens. Sections A–C are the building blocks; D is the entity ladder that screens compose from; E is one shell per GG-5 band; F is the control clusters that travel together. Nothing here belongs to a single screen — if it did, it would live on that screen's plate instead.

C.8 Unit classes — nine, because four was wrong

Every magnitude belongs to exactly one class, and the class decides both how it renders and what it may be compared against. The stack doc committed to four families with a single resolverPoints bucket. Checked against code, six of the twelve combat families are flat game units and six are sigmoid — CombatDerivedReader.Power has exactly one call site and it never touches Sigmoid. One bucket would render six families 10× wrong and put +9 hp and +5 accuracy in the same column.

Why one affix cannot print a percentage. For the four SigmoidPoints channels, p = 1 / (1 + e−delta/100), so the same +10 points is worth +0.73 pp against the shipped lawn baseline and +2.50 pp at neutral — a 3.4× spread. Printing one of those numbers asserts an opponent the player has not met. So the points are authoritative, the estimate is secondary, and the reference is named in the line or the estimate does not ship.

The one class that renders no estimate at all. StatusPotencyPoints feeds two different things from one number: a sigmoid decides whether a status lands, while netFactor = clamp(delta, 0, 10000) multiplies both its magnitude and its duration. An ungeared actor sits at delta = 1.0, so +1 status power doubles every status the wearer applies and the smallest authorable roll is a 2× multiplier. That is either an extraordinary affix class or a normalisation nobody wrote. Until it is answered, the raw magnitude renders and the estimate is suppressed — this kit does not render a number it cannot explain. spec-magnitude-and-units.md §3–§4 · OverlayCombatCalculator.cs:84–99 · ResistanceEvaluator.cs:155–217 · StatComposer.cs:24–31 · ShieldRuntime.cs:121, 403

Three things this ladder settles that nothing in the shipped kit could.
1 — The value line is generated, not authored. Kind + channel + unit family + sign convention produce the sentence; content supplies numbers. Sign is per kind, not global: a negative resource.delta is damage, and a negative stat.modify on a lower-is-better channel is an improvement.
2 — Only a rolled line gets a bar. Five segments, and the three-way split comes straight from RollPolicy: Fixed gets no bar (a full bar would be a lie about the item's luck — nothing could have rolled otherwise), OnInstantiate gets one, and OnApply shows the band, because the item did not roll it, the hit does.
3 — Unsupported is a designed state. The third card is what an atom looks like in a host that cannot execute it — visible, explained, in player words, with the developer four-state badge only in the authoring surface.
4 — No ids, no tiers, no per-mille, and no unreferenced percentage. A tier is an authoring band and T4 invites a wiki; 250‰ is 25%; and “raises crit from 7.6% to 26.9%” asserts an opponent the player has not met — the same affix is worth +0.73 pp at the lawn baseline and +2.50 pp at neutral, a 3.4× spread. The estimate ships only with its reference named. spec-magnitude-and-units.md §3–§6 · item/ssot-presentation.md §3.2 · atom-catalog-ssot.md §2–§4 · definitions.md §2, §9

D.3 Comparison — a mode of the ladder, not a seventh rung

Anything the player can choose between is comparable against what they already have, side by side, as the default presentation while choosing. This is the core loop of an itemisation game, and it is the rule that decides component shape: a card built only to display an entity cannot later be asked to display a difference. GG-47

Every cell is now closed — for the eleven entities in the inventory. That inventory is incomplete: step 1 never swept architecture/item/ (31 docs) or architecture/action/ (11 specs), so 29 entities have no rung at all. See gap-audit-2026-08-22.md. Within the eleven, a rung marked n/a is a deliberate refusal, not an omission: an atom has no panel because a container is the panel an atom appears in; a resource has no row because a meter is its only useful form; a contract has no token because a pact is never small enough to be one glyph. Where a rung is closed on a later plate, the link says which.
What is deliberately not here. Screen layouts (they get their own plates), the home stage (blocked on the owner decision about what home is), art direction beyond framing and colour, and the developer tree's own kit. Also absent: any component bound to the contested resource list — the meter takes a registry row, so the argument can be settled after the foundation ships.
