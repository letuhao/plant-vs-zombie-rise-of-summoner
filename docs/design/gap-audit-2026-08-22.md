# GUI gap audit — the data structures the design set never drew

**Status:** Audit, 2026-08-22. Read-only. No design work in this file — it is the register that says
what detail design is owed and why.

**Audits:** the design set ([README.md](README.md), [information-architecture.md](information-architecture.md),
the eight plates), the capability map
([../architecture/game-gui-map.md](../architecture/game-gui-map.md)), and the plan
([../../tasks/game-gui-plan.md](../../tasks/game-gui-plan.md) /
[game-gui-todo.md](../../tasks/game-gui-todo.md)).

**Verdict: 40 findings — 29 missing components, 8 defects in components that exist, 3 stale
citations.** They share one root cause, and it is a process defect, not a taste disagreement.

---

## 1. Root cause — a partial sweep, declared complete

[README.md §6](README.md) is titled *"Entity inventory (step 1 output)"* and says it was
*"Extracted from the SSOTs."* It lists eleven entities and closes with:

> **anything missing from here is missing from the kit by definition.**

That sentence is correct, and it is the problem. §6 swept eight documents:
`effect-atom/atom-catalog-ssot.md`, `effect-atom/definitions.md`, `unique-actor-runtime.md`,
`actor-hub-ssot.md`, `element-hub-ssot.md`, `world-map-program.md`, `demon-system-map.md`,
`match-runtime.md`.

It did not sweep:

| Not swept | Size | Contains |
|---|---|---|
| [`architecture/item/`](../architecture/item/) | **31 documents, 21 037 lines** | 13 lanes + 4 gap lanes, every one player-facing |
| [`architecture/action/`](../architecture/action/) | 11 specs, 1 445 lines | the action model, costs, targeting, usability, the battle grid |
| [`architecture/shield-system-spec.md`](../architecture/shield-system-spec.md) | shipped code | 4 derived families × 7, cascade, absorb math |
| [`architecture/status-ssot.md`](../architecture/status-ssot.md) | 358 lines | read secondhand through `atom-catalog-ssot.md` §5 only |
| `architecture/{battle,combat,standalone,world,demons}/` | 29 specs | |

**One of those omissions is decisive.** [`item/ssot-presentation.md`](../architecture/item/ssot-presentation.md)
is a 1 278-line document whose stated scope is *"the presentation contract: atoms to text a player can
read"* — the item card blocks in order, the unit ledger, the line grammar, roll-quality rendering,
comparison rendering, localisation shape. **It is the FE's contract**, and it explicitly cedes
*"UI layout, component code, CSS, routing"* to `docs/web/spec.md`
([ssot-presentation.md:52](../architecture/item/ssot-presentation.md)) — a seam the design set never
picked up from the other side.

The design set does not cite it once.

Because §6 is load-bearing by its own declaration, the omission propagated deterministically:
kit → eight plates → the §G coverage matrix ("*Every cell is now closed*") → the 14 modules → the
**sealed** view contract → the 24 tasks. Nothing downstream could have caught it, because every
downstream artifact validates against §6.

### What this is not

It is not that the plates are ugly or that entities were drawn badly. Nine of the eleven ladders are
sound and cite their sources. The failure is confined to **which entities got a ladder at all**, plus a
short list of renderings drawn against the atom SSOT when a presentation SSOT existed and won.

## 4. Class B — defects in components that exist (8)

These ladders were drawn against `effect-atom/`, which is the right SSOT for what an atom *is* and the
wrong one for what a player *reads*. [`ssot-presentation.md`](../architecture/item/ssot-presentation.md)
owns the second question and contradicts the plate on six points.

| # | Where | What it does | What the SSOT says |
|---|---|---|---|
| B1 | [00-foundation.html §D.1](00-foundation.html) rung 3 | Prints `atom.elemental-power.fire.t3` | §2.4: atom / family / container / instance ids are **debug surfaces only** |
| B2 | §D.1 rung 4 | `T3` · `T4` · `T5` tier badges on player cards | §2.4: *"tier numbers. A tier is an authoring band … and 'T4' invites a wiki"* |
| B3 | §D.1 card | *"raises critical strikes from about 7.6% to about 26.9%"* | §3.2.3 **rejects** the bare derived percentage as *"A lie"* — the marginal value of the same affix swings **3.4×** across the opposed-delta range. §3.2.4 requires the reference **named in the line**: `≈ +7.4 pp vs neutral` |
| B4 | §D.1 chip and row | `250 ‰` shown as per-mille | §2.4 lists *"per-mille as per-mille"* under what the player never sees; §3.3 rule 1 adopts the **shipped** helper (÷10, one decimal, trim `.0`) |
| B5 | §D.1 row | `rolled 120–180` as text; `fixed` as text | §3.4 picks a **five-segment bar** and a three-way `RollPolicy` split. A `Fixed` line gets **no bar** — a full bar there is a lie about the item's luck |
| B6 | §D.1 / §C.5 | No `Increased` vs `More` distinction | §3.2.6: `Increased` sums, `More` multiplies ([StatComposer.cs:25](../../src/FusionRpg.Core/Stats/StatComposer.cs) vs `:31-32`). `+15% hp` vs `×1.15 hp`. Rendering both as `+15%` erases a real mechanic |

## 6. What this costs, honestly

**It does not invalidate the stage/layer model.** GG-1…GG-60, the six bands, the four stages, the nine
layers, the shell, the motion vocabulary and the bundle plan are all untouched by this — they are about
*where surfaces live*, and nothing here moves one. Task 2's GG-11 keystone is unaffected.

**It does invalidate three claims:**

1. [00-foundation.html §G](00-foundation.html): *"Every cell is now closed."* The matrix is complete
   for eleven entities and the entity list is short by a large factor.
2. [README.md §5](README.md): *"Everything else … is drawn."* The exclusion list names six refusals;
   none of them is the item program.
3. `docs/web/spec.md` §4's kit inventory, which enumerates the same eleven ladders.

**Where it lands in the plan.** The 24 tasks are not wrong, they are **thin at Task 15** — the Relics
layer, scoped as *Container card · Atom row · comparison*, is the single task that would have to absorb
nineteen missing components. The realistic outcomes are that Relics splits, or the item surfaces are
explicitly deferred and said so out loud.

## 8. Recommended sequence

1. **Fix the source defect first.** Correct `element-hub-ssot.md:88` (56 → 84) and drop the stale
   Resource conflict from `README.md §6`. Two edits, and they stop the error propagating again.
2. **Re-run step 1 properly** — sweep every SSOT, publish a complete entity inventory, and record the
   count. That is the artifact the eleven-entity list should have been.
3. **Do not seal the contract until step 2 lands.** Additive extension stays free; reshaping does not.
4. **Write document 1 (magnitude and units) before any other.** It closes six of the eight Class-B
   defects and is a dependency of the rest.
5. **Then documents 2–9**, in the dependency order above, against real plates that cite `file:line` —
   which is the standard this audit was asked to hold them to.
