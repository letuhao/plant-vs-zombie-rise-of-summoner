# Structured review — standalone + demon program specs (2026-08-21)

Four independent review passes ran against the program specs before implementation: an adversarial architecture red-team, a pipeline feasibility audit (verified against `EventIngest`/`RpgStore` code with file:line citations), external prior-art research (determinism, idle loops, gacha economics, event-sourcing, companion-game precedents), and a game-economy critique. This file records the findings that survived, the debates between perspectives, and how each was adjudicated. The spec amendments below are applied; this file is the why.

## Debates and adjudications

### D1 — Full event replay vs compact battle rows (research vs pipeline audit)

Research argued battles should be compact result rows + recorded seed (the deterministic engine *is* the event stream; don't event-source per-hit combat). The pipeline audit compared both options against the actual ingest code and found the compact path creates a second "match happened" write path, loses run-detail parity, and only avoids two small pollution patches. **Adjudicated: lean event replay** — keep the single ingest path, but emit only lifecycle + spawn + die + `match.result` + `board.end` (~40 events/battle, no per-attack damage events; per-actor tallies live in the `BattleReport` stored as `snapshot_json`), and exempt web runs from per-run capture archives (their events are reproducible from the seed).

### D2 — Exclusive capture vs "companion must never gate content" (research vs owner decision)

Companion-game precedent is unambiguous: gating content behind the companion app is the failure mode (content later unlocked for everyone amid backlash), and the durable success (asynchronous, both-directions, strictly-bonus coupling) is the shape our injector already has. The owner's chosen role — some species capturable only in real PvZ runs — stands, **bounded by guardrails**: ≤15% of the species catalog, zero legendaries among them, codex completion milestones trigger at 90% so web-only players claim every milestone, and world-events later rotates a slow web-side path to each exclusive. Exclusivity of *method*, not permanent lock.

### D3 — Pity and rates (economy critique + research, merged)

Both perspectives independently converged on soft-ramp + hard-ceiling pity with visible counters; commercial base rates (0.6%) explicitly rejected as monetization artifacts. Merged numbers adopted into the summoning spec: keep 74/20/5/1 base, epic hard pity at 25, legendary soft ramp +6%/pull from pull 41 with hard guarantee at 55, all counters persistent, cross-banner, and **visible in the UI**.

### D4 — Duplicates (economy critique vs research)

Research favored Arknights-style dupe conversion (capped rank + essence currency); the critique warned any pre-fusion conversion or release valve teaches players to liquidate the commons fusion will need. **Adjudicated: the critique's V1 valve** (Active/Reserve split, species stacking, lock + nickname, no release), with essence conversion noted as a candidate mechanic *inside* the future fusion module.

## Findings adopted into specs (condensed)

**match-source-core** (riskiest module — most S1 findings land here):
1. Ingest stamps `player_id` from `current_player_id` and ignores the envelope — web matches need an explicit-player ingest path (decisions.md note).
2. No `runs.game` column exists and the game-profile "not a DB column" lock forbids one — the charter amendment must qualify that lock; fact source attribution derives via run join, no facts column.
3. Web-match correlation idempotency has no storage — `rpg_web_match_log` (per-player UNIQUE correlation, matchKey, setup, seed) written before ingest; report ingested via a dedicated single-transaction insert, never the shared channel (a replayed `board.start` on the shared channel rolls back and silently drops the whole ≤800-event batch, including live PvZ events).
4. `types`/metrics writers stamp `pvzrh` unconditionally → catalog/metrics pollution; thread the envelope game through and gate metric bumps.
5. `EffectGrantSession` clears on every `board.start`/`board.end` and `UniqueActorService.ObserveEvents` runs on every batch — both must be gated to PvZ-game events or a web battle wipes a live match's grants.
6. Synthetic actor ids are load-bearing: `web:{matchKey}:{n}` — required by `entities` uniqueness, fact dedupe fallback, the XP ledger's run-less dedupe, and unique-actor `last_ptr` matching. (Separately: the XP ledger dedupe has a latent PvZ bug — defeat XP dedupes on the literal `"run"` — filed as its own fix.)
7. `board.end` is mandatory (runs never close or compact without it); timestamps are stamped monotonically by `WebMatchService`, not the engine.
8. Engine determinism machinery must be built, not reused: `ISeededRng` doesn't exist and `SeededCombatRng` wraps `System.Random`, whose seeded sequence is not stable across .NET versions — vendor an owned PRNG (xoshiro/PCG), per-system streams, integer-only combat math, `(engineVersion, rngAlgoVersion, rulesetVersion, seed)` stamps, golden-seed hash suite.
9. Bypassing the Funnel forks combat semantics (merge, caps, `ProcDepthLimit`) — the engine hosts a battle-local Core Funnel + battle sink so web numbers match PvZ numbers.
10. `RoundDurationMs` and per-round tick order must be locked before golden tests — every reused subsystem is millisecond-clocked.
11. Web runs excluded from capture KeepLastN accounting; almanac type-XP suppressed for web runs (demon species ids also live in a disjoint id space); FE live feeds filter by game; SimEngine gains a game override for webrpg e2e.

**element-extension:** four hand-maintained surfaces are the real risk, not iteration (code verified free of literal-5 loops): the 8 element→channel switch maps (miss one → hot-path throw), the ring matrix's fail-open `_ => Neutral` default (miss the light/dark pairs → silently no counter), `ElementFxPalette` (light/dark render white and are filtered from hybrid VFX — now in scope), and the `Count == 40` assertion (success criterion reworded). `ElementRoster` constant is a new named deliverable; element name parsing must reject numeric strings (`Enum.TryParse("42")` succeeds today).

**demon-core:** codex becomes a monotonic lattice (`discovered` never downgrades to `seen`); species catalog gains acquisition flags (summonable / capture-only / event-only); specimen profile gains `nickname` + `locked`; species ids disjoint from PvZ type ids; V1 seed target raised to ≥16 species.

**soul-economy:** earn policy v2 — `ZombieKilled` +1 **capped at 50 counted kills/match** (kills the stall-farm exploit), victory +100 with repeat decay (full for first win per level per day, 50% after), defeat +25 (~5–8 pulls/hour instead of ~20); earn projection moves **inside** the fact-append transaction (crash window closed); codex discovery rewards added as a faucet (25/75/200/500 by rarity; 50%/100% milestones 500/1500); threat model documented (localhost, no auth, honest-server guarantees only).

**demon-summoning:** pull becomes **one gate-serialized transaction** (spend + mints + codex + log; the two-spec atomicity contradiction is resolved in soul-economy's text too); correlation scoped per player and replay validates the stored request; pity v2 + visible counters (D3); second rotating element-focus banner (120/pull, 3× element weight) as the first real spend choice; duplicate valve (D4): Active roster cap 24 + Reserve stacked by species + lock + nickname-at-reveal; V1 playable floor: codex rewards + counters + nicknames are in, and the **Patron demon** (one summoned demon grants a small bounded effect in PvZ runs via the existing grant path) is flagged **ask-first to the owner** — without it or expeditions, V1 demons are inert.

**standalone map (PvZ role guardrails, from D2 + economy critique):** one-axis rule (each PvZ role owns exactly one axis: capture = breadth, booster = tempo, battles = expression, trophies = prestige); booster becomes a rested-style **Blessing** (a real PvZ run charges +50% Soul earn for the next 3 web expeditions, one charge banked) instead of a live multiplier, with PvZ-sourced income intended ≤40% of total; shared battles cap at 2 demon deploys per PvZ run with small additive grants; trophies cosmetic and one-time. Expedition anchors (research): tiers 30 min/4 h/8 h/20 h, slots 2→5, **no stamina**, recall pro-rates to completed ticks, outcome sealed at dispatch by recorded seed; specimens on expedition are soft-locked from PvZ deploy (and vice versa) via a Cold-plane flag, not the UniqueActor FSM.

## Accepted risks (documented, not fixed)

Self-cheat via always-on debug endpoints (single-player, honest-server model); `types` rows duplicated across game ids for shared portraits (icons are keyed without game, so art resolves); guard scripts rely on naming discipline in `Core/Battle/` (no `EntityStatWriter`/`AddPlantHp` tokens).
