| World turn phase order | **Locked**: `Reveal → Movement → Sieges → Production → Growth → Pressure → Events → Snapshot → Intel`. Changing this list is changing the ruleset — it is spelled out in `TurnEngineTests` rather than derived, so it cannot drift quietly. **`Intel` moved from second-last to last on 2026-08-22 (`RulesetVersion` 2 → 3)**: claims settle in `Snapshot`, so recording belief before it left a faction unable to see that its *own* claim had succeeded — it re-filed the order and the engine dropped it as `claim.already-yours`, costing a turn every time. Belief is what you know at the end of the turn, and the end of the turn is after the turn has finished happening. Found by playing twenty turns, not by any test; the final acceptance golden did not move because belief converges within a turn, so only intermediate hashes changed. **`Production` and `Pressure` stopped being pass-throughs on 2026-08-23 (`RulesetVersion` 3 → 4, `loam-turn`)**: `Production` now yields loam per sector into `LoamStock` (capped, overflow reported and lost); `Pressure` runs `SupplyGraph.Run` then draws each component's upkeep from its pooled stock, fading the weakest contributor on a shortfall — a sector at zero stability is lost and unowned, re-claimable like any other ground. The phase *order* did not change, only what two of its members now do. One golden re-bless (`WorldWaveOneAcceptanceTests.GoldenFinalHash`), the module's second and last (the first was `loam-model`'s field addition, `RulesetVersion` unchanged that time). **The post-gate slice's L25 (2026-08-23) is the third**: every new hashed field the five post-gate modules need — `WorldEntityMember.Role`, `WorldEntity.CarriedLoam` (`loam-legions`), `WorldSlot.StructureId` (`structure-substrate`), `WorldSlot.ConstructionTurnsRemaining` (`loam-structures`), `WorldSector.WardenBindingId`/`NeglectedTurns` (`loam-texture`), and `RememberedSlot.StructureId` on the belief side — landed **together, in one batched golden re-bless**, rather than one per module, per an adversarial audit that caught each of the five post-gate specs independently reopening this already-closed budget one field at a time. `RulesetVersion` unchanged (a field-only addition, no behaviour wired yet — same precedent as `loam-model`'s). See [loam/spec-loam-legions.md](loam/spec-loam-legions.md), [loam/spec-structure-substrate.md](loam/spec-structure-substrate.md), [loam/spec-loam-structures.md](loam/spec-loam-structures.md), [loam/spec-loam-texture.md](loam/spec-loam-texture.md). **L27 (2026-08-23, `RulesetVersion` 4 → 5) is the fourth, and a real behaviour change, not a field addition**: `Pressure` retires `SupplyGraph.Starve`/`AttritionWoundMilli` entirely and wires `LegionSupply.Resolve` in their place, after `LoamPhases.Pressure`'s own sector-upkeep draw — a legion beyond its faction's supply now burns its own `CarriedLoam` and is destroyed outright the turn that reserve would go negative, rather than accumulating wounds over ~20 turns. `SupplyGraph.Recover` is untouched. `first-light`'s and `two-hearths`' own `e-dave-legion-1` gained one bearer and a starting `CarriedLoam` (500, a placeholder bootstrap the same shape as G-D's homeworld stock) — the template-side minimum edit needed so a legion with no reserve does not die the instant it steps off owned ground, before it can even clear or claim anything. | Battle time model | **Battles run on virtual time — a discrete-event kernel, never wall-clock.** `1 tick = 1 ms` (integer `long`); a Future Event List ordered `(dueTick, seq)`; turn-based and real-time are the **same** kernel differing only in time-advance mechanism (next-event jump vs fixed-increment step). **A mode is data, not a code path** — enforced by an architecture test that fails if any kernel type references a profile id or switches on a profile enum. Profile is **resolved from an existing content id** (`WaveCatalog.Get(waveId).Profile ?? classic-round`) and **never serialized onto `BattleSetup`** (a field there moves all four expedition hashes). Per-actor FSM `Charging → Ready → Committed → Resolving → Recovering` plus `Downed` (HP ≤ 0 is veto-capable, never a terminal edge); `Incapacitated` is a **derived read** from StatusRuntime, never a cached remainder. Readiness accrues **work**, not a precomputed deadline, so mid-flight haste takes effect on the current turn. In scope by owner decision: reaction lane, side-scheduled press-turn, multi-actor rendezvous, and live interactive sessions — for which determinism becomes **`(setup, seed, decision-trace)`** and the boot sweep must **refuse** an incomplete trace rather than re-resolve it. ## Why REST and SignalR together

REST survives page refresh and is easy to inspect (`GET /api/stats`). SignalR pushes spawn/die/metrics and `reload-stats` without polling. Raw WebSocket would need reconnect and rooms built by hand.

## Why HTTP fallback on the injector

`Microsoft.AspNetCore.SignalR.Client` may fail to load inside this BepInEx IL2CPP host. The game must still apply last-known stats and ship events over HTTP.

## Why no SQLite in the injector

The plugin must stay a thin hook. Persistence belongs to the server so the web UI works with the game closed.

## Why in-process queues, not Memcached

Localhost, one game, one server. Extra processes add failure modes. Injector `ConcurrentQueue` + server `Channel` + one SQLite writer is the cache.

## Why batch SignalR `Events`, not per-event `Event`

At 120fps a fight is thousands of events/s. One `InvokeAsync("Event")` per row waits on the previous persist. HTTP already posts `{ events: [] }`. The hub must match.

## Why the server stamps `player_id`

The game does not know saves. Later RPG is per-save, not per-PC. Current player lives in SQLite; child rows copy `player_id` from the run opened at `board.start`.

## Risks (do not block v1)

See [research/open-questions.md](../research/open-questions.md):

- Whether `Plant.Start` HP is final
- Whether `attackDamage` or `Bullet.Damage` is the real ATK
- Whether SignalR.Client loads in BepInEx (HTTP fallback covers this)
