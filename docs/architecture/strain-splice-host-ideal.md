# Strain/Splice hosts and tiered runes — the ideal

**Status:** idea phase, 2026-09-12. Not a spec. No build authorized.

**Program:** `strain-splice-host`. Map (when approved) → `docs/architecture/strain-splice-host-map.md`; plan → `tasks/strain-splice-host-plan.md` + `tasks/strain-splice-host-todo.md`. Parent program: `item` (lane I4 sockets + module 21 `strain-splice-gen`). This doc does not amend `item-ideal.md`, `ssot-sockets.md`, `spec-sockets.md`, or `spec-strain-splice-gen.md`; it names the host-restriction and rune-tier layer those docs leave open.

## Which loop this extends

- **Spine C — item collection and progression** (`docs/guide/the-loops.md`): find, vault, equip, compare, craft, socket, salvage. Host-restricted, rune-tiered combinations give low-rarity bases a permanent job: find a cheap chassis of the right slot, open its sockets, earn the runes, build the word.
- **Combat depth** (hangs on places, not an eleventh loop): the fight language every place uses. A Strain grants mechanisms (a proc, a rider, a spawn — never a volume discount with a name), tuned through the one power ladder, never a second ring or new elements.

A feature that needs a new named loop stops here — adding a loop is an owner edit to `the-loops.md`. This one does not. The lawn stays the first core loop, not the whole game; expeditions stay forever; no fourth stock, no class, no stamina gate.

## What this is

In the player's language: a Strain or Splice is a named recipe you build *inside* one cheap item, Diablo-runeword style — four runes in a row, in the right kind of base, and the item wakes up with a new power. Higher powers demand higher-rank runes and bigger bases: a helm tops out at three sockets and can never grow a fourth, so no helm ever hosts a four-rune word; a breastplate can. The base stays what it was — socketing a god-word into a chaff breastplate does not turn it into an heirloom; the word is the prize, the base is the plan.

In system language: three rules that stay separate. (1) **The host stays low-rarity** — a combination binds alongside the host and never mutates it, so rarity never moves. (2) **Runes have ranks, combinations have tiers, and the tier ladder is graduated** — a higher granted tier requires higher-tier ingredients (today only a flat floor exists). (3) **Each slot has its own socket ceiling, owned by tuning** — helm 3 is a tuning row, not a code branch, and crafting tops up to the base's max, never past it.

Load-bearing principles, restated where they bite (a downstream session reads this doc, not its links):

- **Every RPG feature lives in the RPG layer, never by changing what PvZ is.** Sockets, inserts, and combinations resolve in our own stat/effect/combat stack — never in plant/zombie fields. "Does the lawn support a 4-rune word" is the wrong question; "does the RPG layer have the container/evaluator/tuning for it, and is it wired?" is the right one.
- **One power ladder, no private `f(level)`.** Contests read `Θ` (linear, difference-based); magnitudes read `P(Θ)`. A combination tier reuses the shipped affix ladder, never invents a skill-only curve. A Strain grants mechanisms, not magnitudes, so it cannot become a second ladder wearing a name.
- **The balance surface is data.** Socket ceilings, rarity grants, ingredient floors, granted tiers, combination budgets, and all costs live in versioned tuning JSON (`data/tuning/sockets.v{n}.json`, `data/tuning/strain-splice.v{n}.json`), never a `const`. Structural constants (circuit size 4, capacity ceiling, `PowerVector.One = 1000`) stay `const` with a comment saying why they are not tunable.
- **No hard progression ceilings.** A socket ceiling is a per-slot legibility budget, not a player-progression wall — it is the exempt structural kind and must say so in a comment. Caps on magnitudes are soft/configurable; absolute bounds throw, never silently clamp. Refusing an insert because a tuning budget was reached turns a number into a wall — the evaluator suppresses the lowest-priority combination instead and says which and why.
- **Gameless-first is capability, not the pitch.** Socketing and combining must stay usable with the game closed after unlock; the injector may enrich, never permanently gate.
- **Seed → concrete → per-player.** Seedsmith emits seeds (enums, offline, committed, no magnitudes). The runtime rolls concrete per player, seeded. The model writes identity (names, flavour, family picks); deterministic code writes magnitude — enforced by schema audit, never by review.
- **A guardrail validates the contract and closed enums, never a population count or generated text.** Corpus sizes (25 legacy words, 76 shipped combinations of a 102 grid, 1,178 base types) are readings that grow as content ships, never acceptance values. Tests assert joins, uniqueness, determinism, envelopes, and closed-vocabulary membership.

## Prior art

Numbers and failure modes, not vibes. Unverified flags kept as unverified.

- **Runes are a 33-rank ladder, El#1 → Zod#33, and the cube makes the ladder climbable at a published exchange rate.** Low/mid: 3× same rune up to Thul (`3 El→Eld→Tir→Nef→Eth→Ith→Tal→Ral→Ort→Thul`); Thul→Dol add a chipped gem per step (`3 Thul + Chipped Topaz→Amn`, `+ Chipped Amethyst→Sol`, `+ Chipped Sapphire→Shael`, `+ Chipped Ruby→Dol`); Dol→Pul add chipped/flawed (`3 Dol + Chipped Emerald→Hel`, `3 Hel + Chipped Diamond→Io`, `3 Io + Flawed Topaz→Lum`, … `3 Fal + Flawed Ruby→Lem`); Pul→Zod halve the ratio and climb the gem grades (`2 Pul + Flawed Diamond→Um`, `2 Um + Topaz→Mal`, `2 Mal + Amethyst→Ist`, `2 Ist + Sapphire→Gul`, `2 Gul + Ruby→Vex`, `2 Vex + Emerald→Ohm`, `2 Ohm + Diamond→Lo`, `2 Lo + Flawless Topaz→Sur`, `2 Sur + Flawless Amethyst→Ber`, `2 Ber + Flawless Sapphire→Jah`, `2 Jah + Flawless Ruby→Cham`, `2 Cham + Flawless Emerald→Zod`) — `https://www.purediablo.com/diablo-2/horadric-cube-recipes`, `https://diablo2.diablowiki.net/Rune_list`. Our analogue is exact: gem upcycle `3 × tier k → 1 × tier k+1` (`spec-sockets.md:214`) is the low-rune 3:1 leg; what we lack is the high-rune 2:1 leg plus gem-grade climb — a tuning decision, not a code shape.
- **A runeword's level ≈ its highest rune, and its cost is its runes.** "Runewords almost always have a Clvl equal to that of the highest level rune" (`diablo2.diablowiki.net/Rune_list`); examples: Stealth `Tal(8)+Eth(5)` → Clvl 17, Lore `Ort(9)+Sol(12)` → 27, Spirit `Tal(7)+Thul(10)+Ort(9)+Amn(11)` → 25, Enigma `Jah(31)+Ith(6)+Ber(30)` → 65, Chains of Honor `Dol(14)+Um(22)+Ber(30)+Ist(24)` → 63 (`https://www.purediablo.com/diablo-2/runewords`). Trade value is Ber-denominated (Sur slightly <½ Ber; Jah = 2 Ber + sapphire cost; Cham ≈ 1.6 Ber, Zod ≈ 1.7 Ber per forum price math — player-reported, treat as market reading not SSOT — `https://us.forums.blizzard.com/en/d2r/t/idea-to-break-down-runes/149687`, `https://maxroll.gg/d2/items/rune-value`). Design steal: our `GrantedTier = BaseTier + attuned` (`CombinationEvaluator.cs:58`) prices the *word*; Diablo prices the *runes* (highest-rune Clvl + Ber-denominated trade). The graduated ladder we owe is the bridge: higher word tier ⇔ higher `minTier` floor on its runes.
- **Bases are restricted four ways, and every way bites.** (1) Grey non-magical only — no Set/Unique/Rare/Magical even with correct sockets; (2) exact type ("swords only means it"); (3) **exact socket count** — a 3-rune word in a 5-socket item silently yields only the four runes' individual bonuses; (4) exact rune order (`diablo2.diablowiki.net/Rune_FAQ`; `https://rankedboost.com/diablo-2/runewords/helms`). Ours keeps (4)-as-unordered by owner ruling D41 (same inserts any arrangement → same combination — `spec-sockets.md:347`), keeps a weaker (2) as role/frame pin, keeps D21's non-magical analogue as non-set exclusivity (`SetExclusivityValidator.cs:32`), and does **not** keep (3): our evaluator reads a fill, not an exact-count socket row — `minSockets` is a floor, `socket-add` caps at base max. Copying exact-count would contradict the top-up economy (a bad roll is a cost, not a discard — `ssot-sockets.md:136`).
- **Helms top out at 3 — structurally, in Diablo's own tables.** Cube recipe `Ral + Thul + Perfect Sapphire + Normal Helm` rerolls sockets with odds 1:16.7% / 2:16.7% / **3:66.7%** (`rankedboost.com/diablo-2/runewords/helms`); farmable 3-socket bases need area level 41+ (roughly Nightmare Act 2), with per-base qlvls (Normal: Mask 19, Great Helm 23, Crown 29; Exceptional: Death Mask 48, Winged Helm 51, Grand Crown 55, Tiara 70; Elite: Demonhead 74, Spired Helm 79, Bone Visage 84, Corona/Diadem 85 — player-compiled, plausible, treat qlvls as approximate) (`https://us.forums.blizzard.com/en/d2r/t/where-to-find-a-base-for-bulwark/169441`). Helm words are all 2–3 socket (Lore 2, Dream `Io+Jah+Pul` 3, Delirium `Lem+Ist+Io` 3 — same page). Our mirror: `head-guard: 3` tuning row + corpus max 3 + generic cap. Diablo's 3 is a base-table fact; ours is a tuning row — same player-visible outcome, tunable without a rebuild.
- **The documented failure mode is the base hunt, not the rune hunt.** Spirit shield needs a 4-socket Monarch (level 54, 156 strength; earliest non-paladin 4os shield; Hell Cows/WSK/Chaos), while the sword half needs only a Normal-Cows Crystal Sword (ilvl 26–40) (`https://diablo2.io/runewords/spirit-t3.html`, `https://d2db.net/runeword-bases-guide`). Zero-socket bases trade *above* socketed ones because Larzuk guarantees max sockets on normal-quality greys; ethereal for mercs; Mage Plate vs Archon Plate vs Dusk Shroud is a strength-vs-defense-vs-reuse triangle (Enigma has no %ED so flat defense + low strength wins; Chains of Honor has %ED so high defense wins — `https://us.forums.blizzard.com/en/d2r/t/runeword-item-base-question/140128`). Consequences for us: (a) keep the chase in the *base* (role + ceiling + overlapping rarity bands), not in rune rarity alone; (b) never let the word change the base (no %ED-style magnification surprise — our magnitudes come from atoms through `numerics`, never from base defense); (c) rune drops ignore magic find (forum-reported, widely repeated — `https://diablo2.io/forums/obtaining-a-jah-t603500.html`), so volume farming gates high words, which is exactly why our material-grade gate (crafting idea `:130`) must stay separate from rarity overlap.
- **The cost of getting it wrong is priced in centuries of hours.** Hell-Cows Jah cited at 1:654,171 per drop (~300 cows/run → ~2,180 runs → ~220 hours — forum math, **unverified**, method undisclosed — same thread). Whether or not the number holds, the shape holds: an unclimbable top rune with no cube path is a quitting wall, and a downgrade path has real opponents (Cham/Zod would reprice to Jah/Ber and delete niche words like BotD/Plague — `.../idea-to-break-down-runes/149687`). Our 3:1 upcycle with no downgrade inherits the same one-way-valve debate — name it now, price it in module 14, do not let a generator decide it.

## The shape

Three separable rulings. Each states its layer, its owner, and what already carries it.

**1. The host stays low-rarity — a binding-layer invariant, already carried.**
A combination bonus is its own `combo.*` container, instantiated on demand from the socket fill and bound alongside the host (`ssot-sockets.md:98`). Socketing never rolls, never mutates a frozen row, never consumes RNG (`:103`) — the host's `effect_instance`/`effect_instance_atom` rows are written once at drop and never again. So: *filling a Strain/Splice changes nothing about the host's rarity, tier window, or fingerprint.* The word is the prize; the `chaff` breastplate stays `chaff`. No new mechanism; state it as the invariant wherever the low-rarity route is documented, because the current text states the exclusivity (D21: set pieces may not carry — `SetExclusivityValidator.cs:32`) but never the preservation ("the base is not the word").

**2. Rune tiers graduate — the owed ladder, in tuning, not in the generator.**
Today: flat floor `minTierPlan [1,1,2,2]` (`strain-splice.v1.json:7`) + flat grant (`strain: 1, splice: 1` — "start EQUAL" `:10`) + flat size (4 ingredients, `emit.py:127` derived). Proposed: a graduated ladder where a higher *granted* tier requires a higher *ingredient* floor — the Diablo shape (higher word ⇔ higher highest-rune) without Diablo's exact-count or ordering rules (D41 unordered stands; `minSockets` stays a floor). Concretely: extend the existing `minTierPlan` + `baseTier` rows into a per-tier ladder in `strain-splice.v{n}.json` (e.g. tier-1 words floor `[1,1,2,2]`, higher tiers step the floor up — exact steps are balance, not this doc), enforced by the existing most-specific-first matcher (`CombinationEvaluator.cs:174`) with cheapest-first fill (`:189`). The model authors no tier, no floor, no grant — `schema.py:19` already forbids all three; the ladder arrives as tuning the matcher reads. Gems need no new rank vocabulary to start: the five stackable tiers + 3:1 upcycle already climb; El→Zod-style named ranks are a later presentation decision (runtime catalog, never the number file — `tunables-ssot.md:44`).

**3. Each slot keeps its own ceiling — tuning rows, generic enforcement, helm 3 stays a row.**
`head-guard: 3` remains exactly what it is: a tuning row (`sockets.v1.json:13`) enforced by entry validation (`SocketMaxCheck.cs:42`, `SocketTuning.cs:235` throws) and the generic craft cap (`SocketOperations.cs:41`). Alternatives rejected, with reasons:

- **Per-base pins for all 102 (each Strain/Splice made for one base item).** Rejected as the default: it multiplies 102 × bases, breaks the 127-vs-45 learnability bar (`spec-strain-splice-gen.md:124` — mitigation already promoted to requirement: compendium reveal + one-away preview, both module 20's), and duplicates what role/frame pins already discriminate (today's 102 live on exactly two roles). Coarse pins stay the rule; a *named-chase* exception (one iconic word pinned to one base, Diablo's Spirit-Monarch shape) is allowed later as content, never as the grammar.
- **Exact socket count per word (3-rune word fails in a 5-socket base).** Rejected: contradicts the top-up economy (`ssot-sockets.md:136` — a bad roll is a cost, not a discard) and the circuit model (a 6/8-host holds one word per complete circuit plus resonance elsewhere). `minSockets` stays a floor.
- **Helm 3 as code (`const`, role branch, craft-time `CeilingFor` arm).** Rejected: the number test (`tunables-ssot.md:32` — would a balance pass change it? yes) puts it in tuning. The craft-time role arm is the one genuinely missing check — file it as hardening of the corrupt-row case, not as the helm rule.
- **Eight-ingredient words on eight-socket hosts.** Rejected by decision (`decisions.md:132`): capacity 8 is two readable four-insert decisions, never one eight-step wiki recipe. Circuit size 4 is the structural, commented const.
- **Rarity change on combination.** Rejected: rarity selects count + tier window at drop (`ssot-rarity.md` axis split); the word selects atoms at socket time. Crossing them makes `high item level = high rarity` (`crafting-coverage-engine.md:130`) — the exact collapse the four-axis split exists to prevent.
