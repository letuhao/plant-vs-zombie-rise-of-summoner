# Spec: content-codegen (E23)

**Status: BUILT 2026-08-23, retrospective spec written 2026-09-03.** Module **E23** in the
[effect-atom map](../effect-atom-map.md) §3, Wave 6, Checkpoint F. This document records what shipped;
it is not a plan. Acceptance evidence: [tasks/effect-atom-todo.md](../../../tasks/effect-atom-todo.md)
(search `E23: content-codegen`). Scoped from [completeness-audit.md](completeness-audit.md)
finding B2.

> Reads [definitions.md](definitions.md), which wins where it and this document disagree.

## What it owns

`tools/ElementEnumGen` — one CLI with five modes covering three pieces of hand-written C# that mirror
`data/seed/**`, plus the checked-in generated catalog that replaced `EffectSeedCatalog` in production.
Precedent for the tool shape is `tools/DemonCatalogGen`.

| Mode | Subject | Shipped mechanism |
|---|---|---|
| `--check` (default) / `--emit <path>` | `ElementTypeId` and its **three** companion switches | verify against `data/seed/elements/roster.json` |
| `--trait-check` / `--trait-emit <path>` | `TraitAtomSource.Shipped()` | verify against the migrated trait containers |
| `--effect-emit <path>` | `EffectAtomCatalog` | generate from `data/seed/atoms/fx-*.json` |

## What it closed

Four values were authored twice — once as rows under `data/seed/**`, once as C# a human kept in step by
hand — with nothing checking that the two agreed. The roster's mirrors turned out to be **four**, not
one: `ElementTypeId` itself plus `ElementRoster.Concrete`/`TryParse`,
`ElementTypeIdExtensions.ToElementId` and `ElementTable.IdOf`.

It also closed E11's Step 4, `EffectSeedCatalog`'s deletion — first reported as blocked "pending a
converter that doesn't exist", which was wrong: `AtomPushCodec.ToDef` (E19) already was that converter
and `MigrationParityTests.MigratedCatalog()` was already calling it. The claim came from a remembered
summary rather than the file, which is the failure mode `DESIGN-GATE.md` names.

## The contract as shipped

**Argument parsing and modes** — `tools/ElementEnumGen/Program.cs:15-140`. Exit codes: `0` clean,
`1` mismatch, `2` could not start (`:13`). The seed root is a positional argument, defaulting to a
`FindUp("data", "seed")` walk (`:29`, `:142-152`).

**Roster check** (`:107-140`, `ElementEnumCheck.cs`): parses `elements/roster.json` through the real
`AtomSeedFile.Collect`, then `ElementEnumCheck.Run` compares it against the four hand-kept mirrors and
prints each disagreement. `--emit` writes the generated source instead. Against the real repo: clean,
`6 element(s)`.

**Trait check** (`:69-105`, `TraitSourceCheck.cs`): collects `atoms` and `containers`, then compares
`TraitAtomSource.Shipped()` against the migrated containers **by calling `TraitAtomSource.FromContainers`
directly** — the same resolution `TraitMigrationParityTests` exercises — so the tool cannot disagree
with the test suite about what "migrated" means. Building this found a real bug: comparing an invented
trait id against `Shipped()` before checking `IsMigrated` threw, because `ModsFor`'s fallback reads
`TraitBattleCatalog.Get`, which throws on an unknown id. Fixed by reordering the check before the read.

**Effect catalog generation** (`:36-67`): globs `atoms/fx-*.json` `AllDirectories`, ordinal-sorted;
`AtomSeedFile.Collect` → `AtomCompiler.Compile(..., RuntimeId.Lawn, 1, hostIsPlanner: true)` →
`AtomPushCodec.ToDef` → `EffectCatalogGen.GenerateSource`. It **refuses to emit** if any atom was
rejected or routed to the runner (`:54-60`) — the replacement for a retired catalog has to compile
whole. `EffectCatalogGen.GenerateSource` (`EffectCatalogGen.cs:15-83`) emits literal C# object
construction in the style of `DemonSpeciesCatalog.Generated.cs`; the 16 real defs' `Params` values are
only `string`/`int`/`double`, so no runtime JSON parsing is needed.

**The generated file** — `src/FusionRpg.Core/Effects/EffectAtomCatalog.Generated.cs:1-13`, an
`<auto-generated>` header naming the tool, the input glob, the compile path and the two suites that
prove it, and saying to edit the seed JSON rather than the file.

**The swap.** All five `EffectSeedCatalog.CreateAll()` call sites now read `EffectAtomCatalog.CreateAll()`:
`Core/Battle/BattleEffects.cs:54`, `Core/Effects/FoundationHarness.cs:28`,
`Core/Effects/SimEffectHost.cs:34`, `Injector/CheatCommandRunner.cs:117`,
`Injector/Effects/EffectRuntime.cs:55`. `RuntimeId.Lawn` generalises safely because none of the five
runtime-gates at load time, and it is the most permissive matrix column.

**`EffectSeedCatalog` is gone from `src/`** (a sweep of `src/` finds only comments referring to it) and
survives byte-for-byte as a frozen test fixture at
`tests/FusionRpg.Core.Tests/Atoms/EffectSeedFixtureOracle.cs`, same namespace, because six unrelated
test files used it as a convenient known-good `EffectDef` source. That closes the audit's actual
concern — drift between two **live** sources — since a frozen fixture cannot drift.

## What it does NOT do

- **It does not generate `ElementTypeId` or `TraitAtomSource.Shipped()` in place.** Both remain
  hand-written (`src/FusionRpg.Core/Stats/Derived/ActorElementTypes.cs:3` and
  `src/FusionRpg.Core/Battle/TraitAtomSource.cs:40`, neither carrying an `<auto-generated>` header).
  The tool **verifies** them and can emit a replacement on request; adopting that emission was never
  done. Only `EffectAtomCatalog.Generated.cs` is actually a generated production file.
- **It does not run as a CI step.** `.github/workflows/ci.yml` invokes `DemonSpeciesGen --check`,
  `DemonCorpusDump --verify` and `ItemSeedValidator`, but never `ElementEnumGen`. Equivalent assertions
  run inside `tests/FusionRpg.ElementEnumGen.Tests`, which CI does run (`ci.yml:99-100`).
- **It does not author content.** Every mode reads `data/seed/**` and compares or emits; none writes a
  seed file.
- **It does not compile runner atoms.** `--effect-emit` refuses them outright.

## How it is verified today

- **Unit** — `tests/FusionRpg.ElementEnumGen.Tests/ElementEnumCheckTests.cs` (7 tests: reordered roster,
  extra element, missing element, a mis-cased id, `GenerateSource` content) and
  `TraitSourceCheckTests.cs` (7 tests: a wrong amount, an invented trait id, a non-`stat.derived` trait
  atom, an item container correctly ignored, `GenerateSource` content).
- **Real-repo checks inside those suites** —
  `ElementEnumCheckTests.The_real_shipped_roster_file_agrees_with_the_real_enum` (`:95`) and
  `TraitSourceCheckTests.The_real_shipped_trait_content_agrees_with_the_real_Shipped_dictionary`
  (`:120`). These are what make the drift check a standing CI gate rather than a manual run.
- **Execution parity, both sides of the swap** —
  `tests/FusionRpg.Core.Tests/Atoms/EffectCatalogExecutionParityTests.cs` runs every real
  `effect-*.json` scenario through the real `EffectScenarioRunner` against freshly compiled atoms, and
  asserts `Assert.Empty(compiled.Rejected)` / `Assert.Empty(compiled.Runtime)` (`:48-49`) and the same
  sixteen ids as the frozen oracle (`:66`);
  `EffectAtomCatalogGeneratedTests.cs` runs the same scenarios against the checked-in generated file
  and re-asserts the sixteen ids (`:21-27`). What DTO comparison never proved was execution — that is
  the gap this pair closes.
- **Standing regression** — `MigrationParityTests` (DTO shape) and `BattleGoldenTests`, both green with
  the swap live.

## Known residuals

- **There is no `--effect-check`.** The catalog has an emitter and no verifier, unlike the other two
  subjects. A value-only edit to an existing `fx-*.json` atom leaves `EffectAtomCatalog.Generated.cs`
  stale and fails nothing unless a scenario golden happens to cover the changed number. Adding or
  removing an atom **is** caught, by the two sixteen-id assertions.
- **`--effect-emit` is undocumented in the tool's own usage header** (`Program.cs:7-11` lists four
  modes; `:25` implements a fifth).
- **Two of the three subjects are checked but not generated** (see "What it does NOT do"), so the
  hand-written mirrors are still hand-maintained — the tool makes drift loud rather than impossible.
- **Two CI gates here are shaped to today's content and will trip on the first new row**, as
  [effect-atom-map.md](../effect-atom-map.md) §16 records: the sixteen-id assertions, and
  `Assert.Empty(compiled.Runtime)`, which Wave 7's E26 deliberately violates. Each needs a named change
  rather than a rename to dodge it.
