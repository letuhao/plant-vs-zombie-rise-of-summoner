## ⛔ The founding constraint — binding on every task below

> **This system is built and tuned BY DATA. A human cannot help.**
> Every acceptance criterion is a command that exits non-zero on failure. **No step requires a human to
> look at anything** — there is no GUI, no operator, and nobody who can watch a fight, read a table, or
> sign off a value.

**And only a real system run produces real balance data.** The closed form proves self-consistency; the
simulator falsifies the closed form; **neither balances the game**. That is Phase 9, and it is gated on
the complete build ([plan §0.1](class-system-plan.md)).

So:

- **No "review the output"** — a script asserts the number and fails.
- **No "confirm it looks right"** — the expected value is checked in as a baseline and diffed.
- **Runtime behaviour is proven by emitted metrics**, following the shipped `prove-*.ps1` →
  `_prove-*.json` pattern (`scripts/prove-overlay-combat.ps1`) and the perf stream's
  `_baseline-*.json` pattern — never by watching a fight.
- **A judgement that cannot be mechanised does not become an acceptance criterion.** It becomes a
  logged number with a threshold, or it is dropped.

**Phase V builds the instruments the other phases assert against, and it comes first for that reason.**
**Phase 9 runs the tuning loop on real data, and Phase 8 builds and proves that loop on simulated runs
first** — a tuning loop first exercised on real data is a loop debugged during the one window where the
data matters.
